# Подключение frontend к backend

## Базовый адрес и авторизация

Локальный frontend использует `NEXT_PUBLIC_API_URL=http://localhost:8080`; CORS разрешает origin `http://localhost:3000`. Браузер должен обращаться с этого origin: `127.0.0.1` считается другим origin. Для защищённых запросов передавайте `Authorization: Bearer <accessToken>`, для JSON-тела — `Content-Type: application/json`. Cookies не используются.

`POST /api/auth/register` создаёт учётную запись с ролью `Student` и не выполняет вход. `POST /api/auth/login` возвращает `accessToken`, `tokenType: "Bearer"` и `expiresAtUtc`. JWT действует один час, допуск проверки времени — одна минута. При `401` потребуется повторный вход: refresh-токенов нет. Ключ подписи хранится только на backend.

Успешные ответы используют `camelCase`, GUID — строки, даты — UTC в ISO 8601. Статусы прогресса передаются строками `NotStarted`, `InProgress`, `Completed`.

## Последовательность интеграции

1. Регистрация и вход; затем `GET /api/auth/me` для получения текущего профиля.
2. `GET /api/courses?page=1&pageSize=20` — объект с `items`, `page`, `pageSize`, `totalCount`. Каталог содержит только `Published`.
3. `GET /api/courses/{id}/structure` — модули, темы и уроки в `topics[].items`. Поля `content` в дереве нет.
4. `GET /api/lessons/{id}` — содержимое урока. Для опубликованного урока опубликованного курса достаточно JWT; запись на курс не нужна. `isAccessible` в структуре отражает именно доступ к содержимому, а не право изменять прогресс.
5. `PUT /api/me/enrollments/{courseId}` — записать пользователя; `GET /api/me/enrollments` — перечитать собственный список.
6. `PUT /api/me/lessons/{lessonId}/progress` с `{"status":"Completed"}` — сохранить прохождение. `GET /api/me/courses/{courseId}/progress` — получить сводку.

Перед записью прогресса frontend должен учитывать запись на курс, но решение о доступе всегда принимает сервер. После архивации курс закрыт для прохождения; собственный сохранённый прогресс доступен для просмотра. Конкурирующий ответ клиента не следует трактовать как окончательное состояние: после нескольких разных обновлений перечитайте сводку.

## Обработка ошибок

Контент, запись и прогресс возвращают ProblemDetails. Проверяйте HTTP-код; `400` может содержать словарь `errors`, `403` означает недостаток доступа, `404` — отсутствие ресурса, `409` у управления курсами — конфликт состояния, `503` — временную недоступность. `401`/`403` middleware могут иметь пустое тело. Не пытайтесь безусловно разбирать каждый ответ как JSON.

Регистрация и вход сохраняют прежние контракты: например, конфликт регистрации содержит `message`, а ошибки формата запроса — `errors`. Не требуйте от этих методов ProblemDetails во всех случаях. В формах PATCH профиля и курса нельзя передавать `null` вместо пропущенного поля.

OpenAPI доступен в Development по `/openapi/v1.json`; преобразование схем PATCH профиля и курса сохраняется. При запуске Compose сначала применяются обе существующие миграции, затем запускается backend. Миграции этой интеграции не добавляются. Не удаляйте PostgreSQL volume при перезапуске: backend не хранит прогресс в памяти.

Для проверки демонстрационного курса нужны модуль, тема и уроки: API управления их содержимым пока нет. Подготовьте эти данные в изолированной PostgreSQL, создайте/опубликуйте курс существующим API автора и пройдите последовательность выше от имени ученика.
