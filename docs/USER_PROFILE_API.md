# API профиля пользователя

Оба метода работают с учётной записью из заголовка `Authorization: Bearer <accessToken>` и доступны пользователю любой роли.

## GET /api/auth/me

Возвращает текущий профиль: `id`, `email`, `firstName`, `lastName` и `roles`.
После обновления профиль можно перечитать с тем же JWT.

## PATCH /api/users/me

Принимает `firstName`, `lastName` или оба поля. Пропущенное поле сохраняет прежнее значение. Пример изменения только имени:

```http
PATCH /api/users/me
Authorization: Bearer <accessToken>
Content-Type: application/json

{"firstName":"Анна"}
```

Пробелы по краям обрезаются. После обрезки каждое переданное значение должно содержать от 1 до 100 символов. Явный `null`, нулевой символ, пустой объект и посторонние поля (`id`, `email`, `roles` и другие) отклоняются. Если хотя бы одно поле некорректно, изменения не сохраняются.

Успешный ответ `200 OK` содержит обновлённый профиль в том же формате, что и `GET /api/auth/me`:

```json
{
  "id": "dce7fa70-278f-474f-b6f5-8c3ef8d7bf5e",
  "email": "anna@example.test",
  "firstName": "Анна",
  "lastName": "Иванова",
  "roles": ["Student"]
}
```

| Код | Причина |
| --- | --- |
| `400` | Некорректный запрос. Подробности указаны в поле `errors`. |
| `401` | JWT отсутствует, недействителен или учётная запись не найдена. |
| `409` | Профиль изменился во время записи. Перечитайте его и повторите запрос. |
| `500` | Ошибка Identity или базы данных. Подробности остаются в журнале сервера. |
