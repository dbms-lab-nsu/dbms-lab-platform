# API учебного контента

API предоставляет каталог опубликованных курсов, карточку курса, дерево
`Курс → Модуль → Тема → Урок` и содержимое урока. Автор курса и администратор
могут просматривать неопубликованный контент по ID.

## Формат

Ответы с данными имеют формат
`application/json`, названия полей — `camelCase`. Идентификаторы — GUID.
Идентификаторы в примерах условные: при выполнении запросов используйте значения из своей БД.

## Методы и доступ

| Метод | Назначение | Требуется JWT |
|---|---|---|
| `GET /api/courses` | Страница каталога опубликованных курсов | Нет |
| `GET /api/courses/{id}` | Карточка курса | Для `Draft` и `Archived` |
| `GET /api/courses/{id}/structure` | Модули, темы и краткие данные уроков курса | Для `Draft` и `Archived` |
| `GET /api/lessons/{id}` | Содержимое урока, включая разрешённый предпросмотр | Да |

Каталог содержит только курсы со статусом `Published` для всех пользователей,
включая автора и администратора. Опубликованные карточки и структура доступны гостю.

Доступ к `Draft` и `Archived` по ID, а также к неопубликованным урокам разрешён:

- пользователю с действующим JWT и ролью `Author`, если его ID совпадает с `Course.AuthorId`;
- пользователю с действующим JWT и ролью `Administrator`, независимо от владельца курса.

Одна роль `Author` не даёт доступа к скрытому контенту чужих курсов. Совпадения ID
владельца без роли `Author` также недостаточно. ID владельца берётся из БД,
пользователь и роли — из проверенного JWT. Для остальных существующий закрытый
ресурс возвращает `403`; запрос содержимого урока без действующего JWT возвращает `401`.

| Возможность | Гость | Обычный пользователь | Автор своего курса | Администратор |
|---|---|---|---|---|
| Карточка и структура `Published` | Да | Да | Да | Да |
| Карточка и структура `Draft` / `Archived` | `403` | `403` | Да | Да |
| Опубликованный урок в `Published` | `401` | Да | Да | Да |
| Неопубликованный урок или урок в `Draft` / `Archived` | `401` | `403` | Да | Да |

В публичной структуре присутствуют только опубликованные уроки. Автор своего курса
и администратор видят все уроки, включая неопубликованные, во всех состояниях курса.
Содержимое уроков в дерево не включается.

Для чтения опубликованного урока опубликованного курса достаточно любого действующего
JWT; запись на курс не проверяется.
Для запроса урока передайте заголовок:

```http
Authorization: Bearer <accessToken>
```

### Метаданные элементов

DTO содержат общие поля:

| Поле | Тип | Значение |
|---|---|---|
| `id` | string (GUID) | Идентификатор элемента |
| `title` | string | Название |
| `type` | string | `course`, `module`, `topic` или `lesson` |
| `requiresAuthentication` | boolean | Требуется ли вход для доступа к элементу через API |

Для метаданных опубликованного курса, модуля и темы `requiresAuthentication = false`.
В предпросмотре `Draft` и `Archived` у этих элементов значение равно `true`.
Для урока — `true`, включая его краткое представление в публичной структуре.
Это требование доступа к содержимому, а не результат проверки текущего пользователя:
значение остаётся `true` и в ответе на запрос с действующим JWT. Для скрытого контента
одного факта входа недостаточно: дополнительно проверяются права предпросмотра.

Краткое представление урока в структуре дополнительно содержит `isAccessible` —
результат проверки доступа текущего пользователя к содержимому этого урока:

| Пользователь | `isAccessible` |
|---|---|
| Гость | `false` |
| Авторизованный пользователь | `true` для опубликованного урока курса `Published` |
| Автор своего курса с ролью `Author` или администратор | `true`, включая неопубликованные уроки и предпросмотр `Draft` / `Archived` |

Поле вычисляется сервисом и не хранится в БД. Для остальных случаев значение —
`false`. Проверка совпадает с проверкой выдачи содержимого урока при том же
пользователе и состоянии данных. Значение `requiresAuthentication` при этом
остаётся `true`: оно описывает требование входа, а `isAccessible` — текущий доступ.

## GET /api/courses

Возвращает `200 OK` и объект `CourseCatalogDto` со страницей каталога.

### Параметры запроса

| Параметр | Тип | По умолчанию | Допустимые значения |
|---|---|---|---|
| `page` | integer | `1` | От `1` до `2147483647` |
| `pageSize` | integer | `20` | От `1` до `100` |

Оба параметра необязательны. Нумерация страниц начинается с 1.
Неверный формат или выход за допустимый диапазон возвращает `400 Bad Request`.

Курсы сортируются по `title`, затем по `id` по возрастанию.
Пагинация применяется после фильтрации опубликованных курсов и сортировки.

### Пример запроса

```http
GET /api/courses?page=1&pageSize=20
Accept: application/json
```

### Пример ответа

```json
{
  "items": [
    {
      "id": "10000000-0000-0000-0000-000000000001",
      "title": "Основы PostgreSQL",
      "description": "Введение во внутреннее устройство PostgreSQL",
      "type": "course",
      "requiresAuthentication": false
    }
  ],
  "page": 1,
  "pageSize": 20,
  "totalCount": 1
}
```

| Поле | Тип | Описание |
|---|---|---|
| `items` | CourseDto[] | Карточки курсов текущей страницы |
| `page` | integer | Запрошенный номер страницы |
| `pageSize` | integer | Запрошенный размер страницы |
| `totalCount` | integer | Число всех опубликованных курсов до пагинации |

При отсутствии опубликованных курсов `items = []`, `totalCount = 0`.
Для страницы за пределами каталога также возвращается `200 OK` с `items = []`;
`totalCount` при этом сохраняет общее число опубликованных курсов.

## GET /api/courses/{id}

Возвращает `200 OK` и объект `CourseDto` с карточкой курса.

Параметр пути `id` — GUID курса. Некорректный формат возвращает `400`;
отсутствующий курс — `404`, существующий, но недоступный пользователю — `403`.
Для `Draft` и `Archived` требуется JWT автора этого курса или администратора.

### Пример запроса

```http
GET /api/courses/10000000-0000-0000-0000-000000000001
Accept: application/json
```

### Пример ответа

```json
{
  "id": "10000000-0000-0000-0000-000000000001",
  "title": "Основы PostgreSQL",
  "description": "Введение во внутреннее устройство PostgreSQL",
  "type": "course",
  "requiresAuthentication": false
}
```

`description` содержит сохранённое описание курса. Модули, темы и уроки
загружаются отдельным запросом структуры.

## GET /api/courses/{id}/structure

Возвращает `200 OK` и объект `CourseStructureDto` со структурой одного курса
с учётом прав текущего пользователя.

Параметр пути `id` — GUID курса. Некорректный формат возвращает `400`;
отсутствующий курс — `404`, существующий, но недоступный пользователю — `403`.
Для `Draft` и `Archived` требуется JWT автора этого курса или администратора.

### Пример запроса

```http
GET /api/courses/10000000-0000-0000-0000-000000000001/structure
Accept: application/json
```

### Пример ответа

```json
{
  "id": "10000000-0000-0000-0000-000000000001",
  "title": "Основы PostgreSQL",
  "description": "Введение во внутреннее устройство PostgreSQL",
  "modules": [
    {
      "id": "20000000-0000-0000-0000-000000000001",
      "title": "Архитектура",
      "description": "Основные компоненты PostgreSQL",
      "sortOrder": 1,
      "topics": [
        {
          "id": "30000000-0000-0000-0000-000000000001",
          "title": "Процессы",
          "description": "Модель процессов сервера",
          "sortOrder": 1,
          "items": [
            {
              "id": "40000000-0000-0000-0000-000000000001",
              "title": "Главный процесс",
              "sortOrder": 1,
              "type": "lesson",
              "requiresAuthentication": true,
              "isAccessible": false
            }
          ],
          "type": "topic",
          "requiresAuthentication": false
        }
      ],
      "type": "module",
      "requiresAuthentication": false
    }
  ],
  "type": "course",
  "requiresAuthentication": false
}
```

### Состав дерева

| DTO | Дополнительные поля к общим метаданным |
|---|---|
| `CourseStructureDto` | `description: string`, `modules: ModuleDto[]` |
| `ModuleDto` | `description: string`, `sortOrder: integer`, `topics: TopicDto[]` |
| `TopicDto` | `description: string`, `sortOrder: integer`, `items: LessonSummaryDto[]` |
| `LessonSummaryDto` | `sortOrder: integer`, `isAccessible: boolean` |

Пример выше соответствует запросу гостя. С действующим JWT опубликованный урок
в этой структуре имеет `isAccessible: true`. Поле `topics[].items` заменяет прежнее
`topics[].lessons`; старое поле в ответе не дублируется.

Модули, темы и уроки сортируются по `sortOrder` по возрастанию внутри своего
родителя. Значения порядка внутри одного родителя уникальны по ограничениям БД.

В ответе отсутствует `content` уроков. Метаданные опубликованных уроков видны
гостю, но чтение их содержимого требует JWT. Автор своего курса и администратор
дополнительно получают метаданные неопубликованных уроков.

Пустые модули и темы сохраняются. Коллекции возвращаются массивами, включая пустые:
`modules: []`, `topics: []`, `items: []`. Структура курса не разбивается на страницы.

## GET /api/lessons/{id}

Возвращает `200 OK` и объект `LessonDto` с содержимым доступного пользователю урока.
Требуется действующий JWT.

Параметр пути `id` — GUID урока. Проверка авторизации выполняется до поиска
урока и валидации параметров контроллера. Без действующего токена ответ — `401`,
в том числе для отсутствующего урока или ID неверного формата.

Для авторизованного запроса некорректный GUID возвращает `400`.
Для обычного пользователя урок доступен, только если он опубликован и его курс
имеет статус `Published`. Автор своего курса и администратор могут читать также
неопубликованные уроки и уроки курсов `Draft` / `Archived`.
Отсутствующий урок возвращает `404`, существующий, но недоступный пользователю — `403`.

### Пример запроса

```http
GET /api/lessons/40000000-0000-0000-0000-000000000001
Authorization: Bearer <accessToken>
Accept: application/json
```

### Пример ответа

```json
{
  "id": "40000000-0000-0000-0000-000000000001",
  "courseId": "10000000-0000-0000-0000-000000000001",
  "moduleId": "20000000-0000-0000-0000-000000000001",
  "topicId": "30000000-0000-0000-0000-000000000001",
  "title": "Главный процесс",
  "sortOrder": 1,
  "content": "Учебный материал о главном процессе PostgreSQL.",
  "type": "lesson",
  "requiresAuthentication": true
}
```

`courseId`, `moduleId` и `topicId` задают положение урока в дереве.
`content` возвращается как сохранённая строка, без преобразования разметки.

Ответы карточки курса, структуры и содержимого урока передаются с
`Cache-Control: no-store, no-cache`, поскольку доступные данные могут зависеть от текущего пользователя.

## Ошибки

| Код | Условие | Формат ответа |
|---|---|---|
| `400 Bad Request` | Неверный GUID или некорректные параметры пагинации | `ValidationProblemDetails` с полем `errors` |
| `401 Unauthorized` | Нет JWT либо токен неверен или просрочен при запросе урока | Ответ существующей JWT-аутентификации; тело может быть пустым |
| `403 Forbidden` | Курс или урок существует, но у пользователя недостаточно прав; для урока JWT уже проверен | `ProblemDetails` |
| `404 Not Found` | Курс или урок отсутствует | `ProblemDetails` |
| `500 Internal Server Error` | Неожиданная ошибка, включая нетранзиентную ошибку БД | `ProblemDetails` |
| `503 Service Unavailable` | Транзиентная ошибка PostgreSQL/драйвера или таймаут | `ProblemDetails` |

`ProblemDetails` и `ValidationProblemDetails` возвращаются с типом содержимого
`application/problem+json`. На публичных маршрутах карточки и структуры курса
гость получает `403` для существующего `Draft` или `Archived`, а `404` — для
отсутствующего курса. На маршруте урока отсутствие, неверная подпись или истечение
срока JWT всегда дают `401` до поиска ресурса; с действующим JWT различаются `403` и `404`.

Пример `404` для отсутствующего курса:

```json
{
  "title": "Content not found",
  "status": 404,
  "detail": "The course was not found.",
  "instance": "/api/courses/10000000-0000-0000-0000-000000000001",
  "traceId": "request-trace-id"
}
```

Для урока поле `detail` содержит `The lesson was not found.`.

Пример `403` для существующего курса без разрешения на предпросмотр:

```json
{
  "title": "Access denied",
  "status": 403,
  "detail": "You do not have access to this course.",
  "instance": "/api/courses/10000000-0000-0000-0000-000000000003",
  "traceId": "request-trace-id"
}
```

Для урока поле `detail` содержит `You do not have access to this lesson.`.

В ответах `500` и `503` содержатся общие сообщения об ошибке и `traceId`.
SQL, строка подключения и стек исключения клиенту не передаются. `traceId`
позволяет сопоставить ответ с серверным журналом ошибки.

Обработка исключений контента применяется только к `CoursesController`
и `LessonsController`. Формат ошибок остальных маршрутов определяется их
собственными обработчиками.

## Расположение реализации

Пути указаны относительно `backend/DBMSLab.Api`.

| Раздел | Файлы и ответственность |
|---|---|
| `Controllers` | `CoursesController.cs`, `LessonsController.cs` — HTTP-маршруты |
| `Application/Content` | `CourseService.cs` — публикация, права предпросмотра и формирование DTO; `ICourseRepository.cs` — контракт доступа к данным; `ContentReadModels.cs` — модели чтения; `ContentNotFoundException.cs` и `ContentAccessDeniedException.cs` — отсутствие ресурса и отказ в доступе |
| `Application/Content/Contracts` | `ContentContracts.cs` — DTO и параметры каталога |
| `Repositories/Persistence` | `CourseRepository.cs` — запросы EF Core через существующий `AppDbContext` |
| `Filters` | `ContentExceptionFilter.cs` — HTTP-ответы при исключениях контента |

Сущности EF Core и внутренние модели чтения напрямую в ответы API не попадают.

## Ограничения текущей модели

Связь урока с темой в существующей модели и БД: `lessons.TopicId → topics.Id`.
Курс и модуль определяются через тему. Поле `moduleId` в `LessonDto` обозначает
родительский модуль темы; схема БД и миграции не меняются.

Исходная модель хранит публикацию, но не содержит отдельного признака открытого
гостевого доступа. Поэтому все опубликованные уроки требуют JWT; индивидуальная
настройка открытых уроков и наследование доступа не реализованы.

У урока нет отдельного краткого описания и состояния архива: в DTO отсутствует
`description`, а публикация определяется `IsPublished`.
Курсы имеют состояния `Draft`, `Published` и `Archived`.
